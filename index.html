Introduction to Temporal

Understanding the fundamentals of Temporal's architecture and concepts.

What is Temporal?

Temporal is a platform for building reliable distributed applications. It handles the complexity of distributed systems by providing durable execution guarantees.

🧩 Core Concepts

  • Workflows: Define business logic as code
  • Activities: Individual tasks within workflows
  • Workers: Execute workflows and activities
  • Task Queues: Route work to appropriate workers

Why Use Temporal for Order Processing?

Order processing involves multiple steps that can fail:

Traditional approach problems
// What happens if payment succeeds but inventory fails?
// What if shipping fails after inventory is reserved?
// How do we retry failed steps?
// How do we handle partial failures?

async function processOrder(order) {
    await processPayment(order);    // ❌ Can fail
    await reserveInventory(order);  // ❌ Can fail
    await arrangeShipping(order);   // ❌ Can fail
    // No automatic retries, no state persistence
}
Temporal workflow solution
// Automatic retries, state persistence, failure handling
export async function orderWorkflow(order: Order): Promise<OrderResult> {
    // Each step retries automatically on failure
    const paymentResult = await processPayment(order);
    const inventoryResult = await reserveInventory(order);
    const shippingResult = await arrangeShipping(order);
    
    return { paymentResult, inventoryResult, shippingResult };
}

✅ Temporal Benefits

  • Automatic retries with exponential backoff
  • State persistence across failures
  • Visibility into workflow execution
  • Easy error handling and compensation

Defining Workflows

Creating the core order processing workflow with Temporal.

Order Processing Workflow

Create the main workflow that orchestrates the entire order process:

src/workflows/order-workflow.ts
import { proxyActivities } from '@temporalio/workflow';
import type * as activities from '../activities/order-activities';

// Configure activity options
const { processPayment, reserveInventory, arrangeShipping } = proxyActivities<typeof activities>({
  startToCloseTimeout: '1 minute',
  retry: {
    initialInterval: '1 second',
    maximumAttempts: 3,
  },
});

export interface Order {
  orderId: string;
  customerId: string;
  items: { productId: string; quantity: number; price: number }[];
  totalAmount: number;
}

export interface OrderResult {
  orderId: string;
  status: 'completed' | 'failed';
  paymentId?: string;
  reservationId?: string;
  shippingId?: string;
  error?: string;
}

export async function orderWorkflow(order: Order): Promise<OrderResult> {
  try {
    // Step 1: Process payment
    const paymentResult = await processPayment({
      orderId: order.orderId,
      amount: order.totalAmount,
      customerId: order.customerId,
    });

    // Step 2: Reserve inventory
    const inventoryResult = await reserveInventory({
      orderId: order.orderId,
      items: order.items,
    });

    // Step 3: Arrange shipping
    const shippingResult = await arrangeShipping({
      orderId: order.orderId,
      customerId: order.customerId,
      items: order.items,
    });

    return {
      orderId: order.orderId,
      status: 'completed',
      paymentId: paymentResult.paymentId,
      reservationId: inventoryResult.reservationId,
      shippingId: shippingResult.shippingId,
    };
  } catch (error) {
    return {
      orderId: order.orderId,
      status: 'failed',
      error: error instanceof Error ? error.message : 'Unknown error',
    };
  }
}

🔍 Understanding the Workflow

  • proxyActivities: Creates activity proxies with retry policies
  • Sequential execution: Each step waits for the previous to complete
  • Automatic retries: Failed activities retry automatically
  • State persistence: Progress is saved between steps

Implementing Activities

Building the individual business logic components that workflows orchestrate.

Order Activities Implementation

Activities contain the actual business logic for each step:

src/activities/order-activities.ts
// Payment processing activity
export async function processPayment(params: {
  orderId: string;
  amount: number;
  customerId: string;
}): Promise<{ paymentId: string; status: string }> {
  console.log(`Processing payment for order ${params.orderId}`);
  
  // Simulate payment processing delay
  await new Promise(resolve => setTimeout(resolve, 2000));
  
  // Simulate occasional payment failures for demo
  if (Math.random() < 0.1) {
    throw new Error('Payment processing failed');
  }
  
  const paymentId = `payment_${Date.now()}`;
  console.log(`Payment successful: ${paymentId}`);
  
  return {
    paymentId,
    status: 'completed'
  };
}

// Inventory management activity
export async function reserveInventory(params: {
  orderId: string;
  items: { productId: string; quantity: number }[];
}): Promise<{ reservationId: string; status: string }> {
  console.log(`Reserving inventory for order ${params.orderId}`);
  
  // Simulate inventory check delay
  await new Promise(resolve => setTimeout(resolve, 1500));
  
  // Check if all items are available (simulate)
  for (const item of params.items) {
    if (Math.random() < 0.05) {
      throw new Error(`Item ${item.productId} out of stock`);
    }
  }
  
  const reservationId = `reservation_${Date.now()}`;
  console.log(`Inventory reserved: ${reservationId}`);
  
  return {
    reservationId,
    status: 'reserved'
  };
}

// Shipping arrangement activity
export async function arrangeShipping(params: {
  orderId: string;
  customerId: string;
  items: { productId: string; quantity: number }[];
}): Promise<{ shippingId: string; status: string }> {
  console.log(`Arranging shipping for order ${params.orderId}`);
  
  // Simulate shipping arrangement delay
  await new Promise(resolve => setTimeout(resolve, 1000));
  
  // Simulate occasional shipping failures
  if (Math.random() < 0.08) {
    throw new Error('Shipping arrangement failed');
  }
  
  const shippingId = `shipping_${Date.now()}`;
  console.log(`Shipping arranged: ${shippingId}`);
  
  return {
    shippingId,
    status: 'scheduled'
  };
}

💡 Activity Best Practices

  • Idempotent: Activities should produce the same result when retried
  • Stateless: Don't rely on local state between retries
  • Deterministic: Avoid random behavior in production activities
  • Timeout awareness: Handle long-running operations gracefully
